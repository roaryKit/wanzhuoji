# 学习教程：把原生微信小程序迁到自己的新主机和空云环境

> 本教程对应0.3.8可移植源码整理版，2026-11-21。源码地址：**https://github.com/roaryKit/wanzhuoji**。项目授权待权利人确认，不能把公开可见和开源授权混为一谈。仅供18岁以上成年人学习开发，不促饮、不声称健康或疗愈效果。

## 学到什么

这不是套一个网页外壳：前端使用原生WXML/WXSS/JavaScript组件，后端是微信云开发函数、文档数据库与存储。可以阅读个人记录、公开审核、人工入桌审批、私有纯文字聊天如何分层实现，也能观察分页、幂等、缓存失效和退出撤权。没有自建SQL或WebSocket服务供一键复用。

最终目标是“用自己的身份和云资源，空业务数据起步”。不是拿原运营环境、账号或用户数据来演示。根README是操作依据，本教程解释每一步为何要做。

## 第一步：下载与认识目录

从 [仓库](https://github.com/roaryKit/wanzhuoji) 下载 ZIP 并解压，或克隆后进入仓库根目录：

```sh
git clone https://github.com/roaryKit/wanzhuoji.git
cd wanzhuoji
```

`miniprogram/`是客户端，`cloudfunctions/`是七个独立函数包；`tests/`是内存隔离测试，不会创建线上账号或记录；`config/`是无凭证模板，`docs/`有架构与权限说明。不要把生产备份当源码，也不要把node_modules或数据库dump提交Git。

摄影和未知来源图标已换成自制几何占位。生产截图不等于可再分发素材，包内没有用户照片或真实体验码。可选模拟配图另包、带明显标识，不作为真实效果或多设备验证证据。

## 第二步：先验证本机工具链

安装Node.js 20+、npm和Python 3，在根目录运行：

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm test
npm run check
npm run scan
npm run check:deploy
```

前四步验证本地安装、回归、语法和启发式扫描。最后一步在原始占位配置上**应拒绝**，这提醒你尚未配置自己的微信目标。根项目不需要第三方测试器；七函数SDK依赖另装，具体命令在README。扫描不是数学意义的无泄漏证明。

当前测试由继承286项加4项可移植/空态检查组成，结果见CHECKS.md。测试里的Map、虚构身份和消息是进程内输入，不是随包导入线上业务的“种子数据”。服务端空列表和四个实际组件空响应已测，不能据此称微信真机全链已通过。

## 第三步：配置私有部署副本，不污染公开源码

再复制一份源码，只在私有副本准备自己的AppID和全新独立云环境：

```sh
node scripts/configure.js --appid "自己的小程序AppID" --env "自己的云环境ID"
npm test
npm run check
npm run check:deploy
```

把中文换成自己的标识。配置脚本不联网、不部署、不注入数据；它还会刷新配置相关文件指纹，让环境字符串变更不被误报为行为修改。不要把配置后的副本提交公开仓库：.gitignore不会去掉已经写在源码中的标识。

离线演练可在另一个临时副本运行 `node scripts/configure.js --example`；它仍过不了部署门控，不能冒充正式配置。AppID/环境要同时改，不能靠传openid来换身份。

## 第四步：空数据库与权限先行

按README创建13个空集合，不导入任何业务记录。每个集合拒绝客户端直接读写，由云函数使用可信身份上下文处理。资料只投影允许展示字段，非成员不读桌内信息；不要为了看头像或调通申请改成公开权限。

检查实际分页、线程、待审与增量查询，按自己控制台报错补齐并验证索引。存储需要本人受控路径写入、私有读取限制和服务端审核后签名；模板是审查清单，不能当作任意平台版本都能一键执行的ACL。当前没有替你验证完整索引或存储规则，这是明确的人工部署环节。

## 第五步：七函数与审核回调

全部业务函数是：initUser、submitRecord、getPlaza、mediaCheckCallback、reportRecord、clearMyData、roundtable。没有附带私有诊断/伪造身份函数。

在自己的微信开发者工具导入根目录，核对目标后逐个“上传并部署：云端安装依赖”。SDK锁定4.0.2，本机可用README中的七条 `npm --prefix ... ci --ignore-scripts` 验证锁文件安装。首次安装需上游公开源网络，不提供带依赖实现的离线大包。

官方文本/媒体审核需要你自己的资质和安全接口权限。回调HTTPS地址、安全模式JSON、服务端Token与43字符AESKey都用自己的配置；不写进Git或前端，也不以测试桩替代真实审核。缺权限时保持待配置/待验，不绕过审核伪造“通过”。

## 第六步：从空态做双角色验证

新环境打开先年龄门控，本人确认后初始化本人设置，不会产生假酒单或假聊天。列表为空是正常起点，创建入口应可见。用你有权使用的两个成年账号：

1. A创建5～8容量桌，B申请；“提交”只是pending，不等于入桌。
2. A从站内待审计数/列表批准或拒绝；没有自动微信推送承诺。
3. 批准后双方检查允许头像昵称、历史和新消息；自己右、他人左，桌主也一样。
4. 验证退出/移除/解散后撤权、跨桌拒绝，私有缓存不能继续显示内容。
5. 验证深浅主题、小屏安全区、胶囊和键盘；真实头像URL、审核和多设备仍需手机证据。

不要在别人的真实申请上演练，不用“自动批准”绕过人工审批。圆桌图片未实现，当前只做纯文字；不要把“后续计划”写成已上线功能。

## 技术阅读路线

- `miniprogram/utils/cloud.js`：请求合并、身份/范围与写后失效；缓存提速不能牺牲撤权。
- `miniprogram/utils/tab.js`和各tab组件：热切换保持内容与位置，首次加载问题要分开测。
- `cloudfunctions/roundtable/roundtable.js`：人工审批、容量、成员索引、消息历史/增量、幂等与权限边界。
- `cloudfunctions/submitRecord/service.js`及同步副本：身份、资料审核、记录与公开投影。不要只改一个副本，`npm run check`会检查一致性。
- `docs/SECURITY_MODEL.md`：信任边界；`tests/mock-cloud.js`只模拟SDK，不能证明真实数据库并发重试或微信内容审核。

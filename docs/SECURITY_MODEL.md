# 权限、审核与真实能力边界

1. 先确认18岁，拒绝或未确认不得绕过业务门槛。身份/AppID/云环境来自平台上下文与配置，而非客户端填写。
2. 数据库集合不允许客户端直读直写，由云函数判断当前人、资源归属、公开范围和成员关系。`config/database-rules.example.json`只是审查清单，不是已经应用的规则。
3. 公开记录/评论和资料使用文本审核及异步图片审核；私密记录不意味着允许公开下载。审核超时/异常不应当假通过。头像昵称只有允许投影的字段，未设置/待审/不可用使用明确兜底。
4. **匿名在当前实现中会隐藏广场和圆桌资料（含本人投影）**；注释中的scope名称不构成额外公开授权。已批准也不会覆盖匿名/审核约束。用户尚未批准的申请不伪装为成员。
5. 圆桌发现卡只展示允许的成员缩略信息；非成员不获取桌内完整资料/历史。申请、审核、转让/移除/退出/解散都服务端核验；退出撤权优先于缓存复用。
6. 消息纯文字，拒绝媒体/富文本，历史媒体为不透明占位；引用不复制私有文件URL。发送clientId/fingerprint与版本/事件游标用于幂等、重试和增量。
7. 微信图片回调仅`mediaCheckCallback`接收，`callback.js`校验AES JSON安全模式、签名、时间窗、AppID和事件类型。配置缺失或伪造回调应拒绝。不要把它替换为客户端声明“审核通过”。
8. 图片由客户端上传到服务端分配/校验的本人目录，服务端校验路径/归属/类型并签发临时链接；这**不能替代存储ACL**。平台存储规则能力随版本不同，需验证只允许本人获准目录写入、私有素材不被无条件读取。无法验证时应禁用相关图片能力，不得把存储桶改为公开读写来修图。
9. 没有端到端加密承诺；云环境运营方拥有的管理权限与成员权限不同。没有微信订阅推送承诺，站内徽标/列表不等于已发微信通知。

源码导出扫描不是完整渗透测试、法务审查或零漏洞保证。正式部署须验证跨账号、退出撤权、跨桌隔离、审核回调、URL到期/下载权限与真机键盘；不可用本地模拟冒充平台验收。
